### 1. HTTP-заголовки 

Для начала решили посмотреть, что показывает сервер в ответ на запрос. Открыли инструменты разработчика в браузере и изучили Response Headers

<img width="536" height="316" alt="Response headers" src="https://github.com/user-attachments/assets/7b7b3455-cf17-4a57-938b-57af701e1baa" />

Видим:

- `Server: nginx` — наш nginx
- `Content-Type: text/html; charset=UTF-8` — сервер отдаёт HTML в кодировке UTF-8
- `Content-Encoding: gzip` — содержимое сжимается перед передачей, чтобы не гонять лишние байты
- `Cache-Control: max-age=1728000` — задаёт время кэширования ответа
- `X-Frame-Options: SAMEORIGIN` — запрещает другим источникам просто так встраивать страницу во фрейм
- `Vary: Accept-Encoding` — ответ может отличаться в зависимости от поддерживаемого сжатия

А вот заголовка Content-Security-Policy (CSP) здесь не оказалось 👀 Он помогает ограничивать источники скриптов и другого содержимого, без него как раз появляются вопросы к безопасности сайта. Но чтобы точно подтвердить эту уязвимость надо отдельно проверить обработку пользовательского ввода и возможность выполнения внедрённого JavaScript, но мы такое не делали, просто пока заметили и запомнили отсутствие CSP.

### 3. Проверяем Path Traversal

Преисполнились что Path Traversal — это ситуация, когда приложение неправильно обрабатывает пути к файлам и позволяет обратиться к тому, что пользователь видеть не должен. Например, последовательность `../` обозначает переход к родительскому каталогу.

Решили проверить реакцию сервера на изменённые пути и понять вдруг удастся получить содержимое файлов за пределами доступной директории

### 4. Проверка доступа к служебным файлам

Дальше смотрим не раскрывает ли сервер конфиденциальные служебные файлы.

Бывает что из за неправильной конфигурации nginx в открытом доступе оказываются файлы с настройками приложения, ключами доступа или информацией о репозитории, вдруг сайт нашей школы как раз так настроен, сейчас проверим

Мы через терминал отправили запросы на .env — файл, в котором могут храниться настройки приложения и секретные данные и .git/config — конфигурационный файл Git, который может раскрывать информацию о репозитории.

отправили запросы через терминал:

curl -I https://school8zav.narod.ru/.env   
curl -I https://school8zav.narod.ru/.git/config

Флаг -I позволяет получить только HTTP-заголовки, не загружая содержимое файлов
.env - это как раз файл где могут храниться настройки и секретные файлы
.git/config - конфигурационный файл Git который тоже может раскрыть доп инфу
